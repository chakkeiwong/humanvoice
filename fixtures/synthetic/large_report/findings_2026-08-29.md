# Phase 1.2 findings — large synthetic document run

Run date: 2026-08-29. Fixture: `fixtures/synthetic/large_report`.
Scope: internal evaluation (G4 Option A). Model: claude-opus-5, real API.

Pipeline outcome: `init` ok → `plan` ok (10 sections / 5100 words) → `draft` 10/10 ok
(2 needed a resample) → `preflight` abstained (exit 2) → `release` blocked (exit 2).

Five defects surfaced. Two are release-gate fail-opens and are the significant ones —
they weaken never-except conditions the contract says can never be bypassed.

---

## F-RELEASE-PATH-001 — release reads a runs directory that plan and draft never write (blocking)

`plan_command.py:217` and `draft_command.py:314` write to:

    Path.cwd() / ".humanvoice" / "runs" / run_id

All five release gates read from (`release_command.py:41,70,140,195,271`):

    snapshot_dir / ".humanvoice" / "runs"

These never coincide unless cwd happens to equal the snapshot dir. In this run the
directory release looked for did not exist at all.

Three gates treat a missing runs directory as *pass*:

| gate | line | behaviour when runs_dir absent |
|---|---|---|
| `check_unresolved_author_choice` | 42-43 | `return None` → pass |
| `check_protected_manifest_correspondence` | 71-72 | `return None` → pass |
| `check_evidence_gaps` | 196-197 | `return None` → pass |

Verified by direct call against the real snapshot — all three returned `None`:

    unresolved_author_choice           -> None
    protected_manifest_correspondence  -> None
    evidence_gaps                      -> None

The check logic itself is sound. Copying the runs tree to `snapshot_dir/.humanvoice/runs`
and planting an unresolved marker made the gate fire correctly:

    unresolved -> {'record_type': 'ReaderDecision', 'status': 'unresolved'}

So this is purely a path-contract mismatch, not broken checks.

Why release still blocked: `check_source_build` reaches a *different* conclusion from the
same missing directory — it blocks with `no_protected_extraction`. The release was
therefore blocked for an incidental reason while three never-except gates were silently
skipped. A snapshot with unresolved correspondence and a valid protected manifest could
plausibly release. Not confirmed end-to-end, since protected manifests are never emitted
at all (F-PROTECTED-002).

Fix: one canonical run-directory resolution shared by all commands. Additionally the
three gates should distinguish "no records exist" from "records exist and are clean" —
absence of evidence should not read as evidence of compliance on a never-except path.

## F-EVIDENCE-003 — evidence gate fails open on missing or unrecognised appraisal_state (blocking)

`release_command.py:216`:

```python
if has_load_bearing and appraisal_state in ("insufficient", "unappraised"):
```

Only two exact strings block. Anything else — including absent, `None`, or a case
variant — passes. Tested with a load-bearing support in each shape:

    missing_appraisal_state    -> PASSES (fail-open)
    null_appraisal_state       -> PASSES (fail-open)
    explicit_unappraised       -> BLOCKED
    typo_state                 -> PASSES (fail-open)

A load-bearing claim with no appraisal recorded is exactly the case the gate exists to
catch, and it is the default shape of a record written by anything that doesn't set the
field. Independent of F-RELEASE-PATH-001: fixing the path does not fix this.

Fix: invert to an allowlist — block unless `appraisal_state` is explicitly one of the
recognised sufficient states.

## F-PROTECTED-002 — no protected-manifest records are ever emitted

The brief promises 9 protected objects. `preflight` extracts 6 citations via pylatexenc
and reports `deterministic_gate: pass`, but no `protected-manifest*.json` is written
anywhere, so `check_protected_manifest_correspondence` has nothing to compare and
`check_source_build` blocks with `no_protected_manifests` once it can see the runs tree.

Consequence: protected-object correspondence is currently unenforceable end-to-end. This
is adjacent to Blocker 2 (evidence-item emission) and probably wants the same fix pass.

## F-TRANSMISSION-004 — the transmission never-except condition has no implementation

`release_command.py:16` lists "unauthorized external transmission" as a never-except
condition. `grep -n transmission src/humanvoice/commands/release_command.py` returns only
that docstring line. `run()` registers five gates: `protected_correspondence`,
`brief_parsing_promises`, `evidence_sufficiency`, `source_build`, `author_convergence`.
There is no transmission gate.

Confirms Blocker 3 is not merely missing instrumentation in `model.py` — the release-side
gate does not exist either.

## F-PLAN-SCALE-005 — target_word_count in brief extensions is ignored

`plan_command._build_plan_prompt` uses `brief.get("max_words", 5000)` and never reads
`extensions.target_word_count`. The fixture asks for 15,000 words / 25 sections; the
blueprint came back with 5,100 / 10 and no warning that the request had been downscaled.

This is why the cost figures cover ~40% of the intended document. Per-section costs stand;
the whole-document projection does not.

## F-REGISTER-006 — register-blocked units produce no repairable artifact (procedural)

Sections 0 and 1 first returned exit 1, "First-person usage detected: 'We'" at offsets
1632 and 48. `draft_command.py:358` returns before `_write_draft()`, so no `.tex` exists.
`hv repair` takes a draft path as its positional argument, so the documented repair path
is unreachable for exactly the units that failed a gate.

Both sections passed on a plain resample (414 and 512 words, 4 citations each), so this
was sampling variance rather than a systematic prompt defect. The recovery path is
"invoke draft again", not "repair" — worth stating in the operator docs, since the plan's
"phase repair between phases" step cannot apply to register-blocked units as built.

Discarded work is real cost: 2 blocked attempts plus 2 superseded resamples account for
13,769 input / 2,005 output tokens, ~28% of input spend for this document.

## Secondary observations

- **`latency_ms` is 0 in all 12 runtime manifests.** Wall-clock had to be reconstructed
  from shell timestamps. Blocks any per-unit operator-time measurement.
- **Input-token cost is non-deterministic across gateway paths.** 3 of 12 calls consumed
  ~12.5-13.2k input tokens against ~1.1-1.3k for structurally identical prompts. The
  split tracks request-ID format exactly (32-char hex = high, 24-char base62 = low), not
  section content or evidence size. Roughly 11x input cost on affected calls, apparently
  a prompt-caching difference between serving paths. External to humanvoice, but it makes
  any published per-document cost figure unreliable until characterised.
- **Preflight cannot clear without a project vocabulary config.** Exit 2, 8 ambiguous
  terms (BLS, TLA, BFT, DAG, GST, …). Needed before any fixture can reach a clean release.
- **Three-way brief required-field mismatch persists** between
  `schemas/authoring-brief.schema.json`, `init_command.py`, and `plan_command.py`. Worked
  around here by putting all three field sets in one brief.
- **Word-budget variance is a warning, not a gate.** Section 6 came in at 1092 words
  against range [720, 1080] and proceeded.

## Bearing on the v1.2 release decision

F-RELEASE-PATH-001 and F-EVIDENCE-003 are the ones that matter for external release. Both
let a never-except gate pass on absent data, which is the failure mode the contract's
never-except language exists to rule out. Cost validation is incomplete for the reasons in
`cost_instrumentation.json` and I would not publish the $3/document figure on this run.
