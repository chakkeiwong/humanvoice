# ZLB inventory punctuation ownership repair

The ZLB run stopped after 18 completed and settled calls. Its sixth processed
window contains the standalone source bytes `:\n` between two protected math
spans. The coverage critic returned `covered` with an empty concept mapping.
Native inventory requires every nonempty prose span to have an owner, including
punctuation. Five windows passed; the sixth was processed but not admitted.
The subsequent transport-continuation error is secondary: no response-free
failure occurred, so the transport-only continuation correctly refused it.

## Prospective rule

Retain original source, requests, responses, receipts, failed stage, settlement,
qualification and completed held-out boundary. Add a versioned policy to a new
SSD snapshot. Derive ownership only for one standalone colon, semicolon, comma
or period with surrounding ASCII whitespace, bracketed by contiguous protected
math in the same file. Exactly one extracted concept must already own both
math spans and substantive source prose, with a positive independent
reconstruction citing both math spans. All coverage and reconstruction rows
must be complete, unique, positive and source grounded. Ambiguity, negation,
operators, missing verdicts and negative judgments remain blocking.

The derived coverage record contains the untouched raw verdict, source context,
concept and reconstruction hashes. Raw provider journals and receipts stay
unchanged. Native baseline replay must reproduce the same derived record and
supporting-span ownership. The policy applies only to snapshots carrying its
exact source-bound marker; historical snapshots retain their original behavior.
