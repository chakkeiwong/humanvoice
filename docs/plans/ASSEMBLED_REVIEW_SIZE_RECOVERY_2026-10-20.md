# Automatic recovery of oversized assembled reviews

The held-out reproduction stopped after both revised units and their reviews
passed and fifteen of twenty-seven assembled windows completed. The next window
returned a complete review of seventy concepts and ninety-eight functions. Its
76,106 input tokens fit the authorized 80,000 ceiling; its 40,963 output tokens
exceeded 32,000. All native semantic checks pass. This is an operational output
failure, not a network error. The original answer, error and charge remain intact.

The existing automatic size recovery covers writers only. Extend the user's
instruction to split failed work to assembled reviews, within existing ceilings:

1. Validate the stopped independent process, all twenty-five allocations and
   the unique settlement. Preserve both repaired writers, every unit judgment,
   the fifteen completed assembled reviews and all historical runtime evidence.
2. In a fresh SSD replica, partition only a proven oversized review. Keep its
   entire source and candidate context in both children. Divide the exact ordered
   concepts into two disjoint groups, preserving all functions, qualifications
   and prerequisite metadata. Use the existing qualified assembled prompt.
   Each child still checks the entire candidate for additions and ordering.
3. Accept only native child responses within 80,000 input and 32,000 output.
   Never repeat the failed parent request or admit its over-limit response.
   Any substantive rejection, invalid evidence, unknown failure or indivisible
   scope stops. Such failures cannot obtain new semantic judgments through splits.
4. Allow depth three and at most fourteen child calls per root. Preserve the
   eleven unrequested roots. Reserve at most 179 new logical calls: fourteen
   children for the spent root and fifteen attempts for each remaining root.
   Carry only the five unspent network extras; response-free eligible failures
   wait 900 seconds. All calls consume the existing 2,000-call and 600-million-
   token grants. Preserve all incomplete charges, including reported usage
   conservatively retained as a full reservation.
5. Independently probe the exact first child without provider calls. Test full
   relationship context, exact concept/function coverage, rejection stops,
   finite decomposition, cache reuse, native runtime admission and accounting.
   Commit the repair and use durable supervision. Activation waits for any
   in-progress probe to release the program lock, then verifies and freezes the
   passing proof before any live execution. A failed probe still stops activation.
6. Carry size recovery into subsequent assembled reviews, including ZLB, with
   explicit finite reservations. Keep native source-fidelity, build, release,
   independent reproduction and final automatic admission mandatory.

Use sixteen verification workers, sequential provider calls, SSD working storage,
read-only archive aliases, and 900-second/$4 audits. At every phase boundary or
stop, inspect, settle, verify, repair and refresh both master documents. Only
final human acceptance of immutable actual ZLB output requires content review.

oversized parent and before its child, exact-request retries, cached child replay,
independent receipt validation, retained failure charges and activation waiting
for concurrent validation before it can execute.
